AFO 611
Utilisateurs et autorisations
611.1 Introduction
Le système dispose d’un certain nombre de mécanismes sophistiqués de sécurité dont le contrôle des mots de passe constitue l’élément principal. La gestion des utilisateurs, AFO 611, vous permet de protéger votre système de manière optimale.
Fonctions et caractéristiques de connexion
Pour ouvrir une session, l’utilisateur doit entrer un ID utilisateur. Ce dernier possède les fonctions suivantes :
• détermination des autorisations au sein du système ;
• détermination de la langue dans laquelle l’utilisateur communique avec le système (néerlandais, anglais ou français).
Les IDs utilisateurs peuvent comporter au minimum trois et au maximum 50 caractères. Les mots de passe peuvent être constitués de symboles numériques, de symboles alphanumériques ainsi que de caractères spéciaux ou de leur combinaison. Les seuls caractères non autorisés sont ^ (flèche vers le haut) _ (tiret bas) et ~ (tilde).
Les données suivantes sont liées aux IDs utilisateurs :
• un nom, affiché lors de l’ouverture de la session ;
• la langue employée par le système afin de communiquer avec l’utilisateur ;
• les fichiers auxquels l’utilisateur a accès ;
• les paramètres auxquels l’utilisateur a accès ;
• un mot de passe ; celui-ci est facultatif (mais son utilisation est recommandée) ;
• les AFO auxquelles l’utilisateur a accès ;
• l’autorisation permettant de démarrer des activités en "mémoire" (c’est-à-dire ultérieurement).
Le système distingue les types d’ID’s utilisateurs:
• l’ID utilisateur système ;
• les IDs utilisateurs possédant un statut particulier
• les IDs utilisateurs "normaux".
L’utilisateur système
L’ID utilisateur système se distingue par rapport aux autres IDs utilisateurs, grâce aux caractéristiques suivantes :
L’ID utilisateur du système offre des possibilités supplémentaires au sein de certains modules du système, par exemple au niveau de la gestion des mots de passe.
L’ID utilisateur système peut passer outre les verrous posés par le système à différents endroits du logiciel.
IDs utilisateurs possédant un statut particulier
AAA – AutomaticSaveLists : Les nouvelles notices bibliographiques et les nouveaux exemplaires seront automatiquement enregistrés dans un des paniers de l’utilisateur appelé « Automatic Save Lists » (code utilisateur AAA). Les paniers sont générés pour les premiers exemplaires ajoutés à une notice et pour les nouveaux exemplaires (par année et par mois).
Le panier AFVGPK contient une liste de notices bibliographiques qui n’ont plus de cote de rangement (tous les exemplaires ont été supprimés).
Utilisation générale : Tout le monde peut voir les paniers automatiques en utilisant l’option « Consulter les paniers de l’utilisateur [PW] », puis en sélectionnant « Automatic save Lists ».
VUBISWEB – WebOpac user: Cela peut être utilisé pour récupérer les informations de transactions liées à l’usager, comme ajouter un nouvel usager, modifier les informations d’un usager via le catalogue public.
PUB – WebOpac Public user: Cela peut être utilisé pour les rapports STI des transactions de prêt via le catalogue public, comme les réservations, les prolongations, les demandes de prêts interbibliothèques.
Uniquement les utilisateurs avec les privilèges SYS! Pour l’AFO 141 sont autorisés à modifier / supprimer le contenu des paniers automatiques.
Les IDs utilisateurs "normaux".
Ce sont tous les autres IDs utilisateurs.
Cryptage du mot de passe
Cette fonction fournit un mécanisme pour permettre aux clients d’utiliser des mots de passe cryptés pour la connexion à l’application (aussi bien qu’aux Preferences du WebOpac). La fonction cryptage est optionnelle. Le paramètre n’est pas interactif et ne peut être paramétré que par le personnel d’Infor.
Autorisation
Divers types d’autorisations sont associés à chaque ID utilisateur. Vous en trouverez une description ci-dessous:
Accès aux fichiers
Chaque fichier bibliographique se caractérise par un numéro. Ces numéros sont associés à chaque ID utilisateur permettant d’accéder aux fichiers.
Accès aux paramètres
Chaque paramètre au sein du système est identifié au moyen d’un code. Ces codes sont associés à chaque ID utilisateur permettant d’accéder aux paramètres.
Accès aux AFO
Les données permettant d’accéder aux différentes AFO sont associées à chaque ID utilisateur.
Attention!
Un ID utilisateur permettant d’accéder à l’AFO 611 "Utilisateurs et autorisations" ne peut offrir un accès à d’autres IDs utilisateurs que pour les AFO auxquels cet ID utilisateur a lui-même accès. Par contre, l’ID utilisateur du système vous permet d’accéder à toutes les AFO.
Sécurité supplémentaire
Outre les mots de passe, le système comporte d’autres mécanismes de sécurité. Vous en trouverez une description ci-dessous.
Mot de passe
Un mot de passe peut être associé à chaque ID utilisateur. Ce mot de passe demeure invisible dans le système. Au sein de la gestion des utilisateurs, vous pouvez déterminer si, pour chaque ID utilisateur, le mot de passe doit ou non être demandé lors de l’ouverture d’une session. Les utilisateurs peuvent eux-mêmes modifier ce mot de passe. Toutefois, cette opération ne fait pas partie de la gestion des utilisateurs, étant donné que le mot de passe en question est invisible même pour l’administrateur du système. Ce mot de passe joue un rôle uniquement lors de l’ouverture d’une session ; les autorisations et autres procédures du même type sont associées à l’ID utilisateur et non pas au mot de passe. Notons qu’il est possible de limiter la durée de validité de ce mot de passe. Quand ce délai expire, l’utilisateur doit modifier son mot de passe lors de l’ouverture d’une session. Le système avertit l’utilisateur lors de l’ouverture de session, quelques jours avant la date d’échéance d’un mot de passe.
Si vous souhaitez utiliser le cryptage pour les mots de passe du personnel, veuillez contacter le service d'assistance Infor. V-smart prend en charge le cryptage AES standard de l'industrie.
Note
Quand Argus est utilisé pour le SSO :
• les utilisateurs doivent avoir un mot de passe
• le système propose l’écran de connexion Argus au lieu de l’écran V-smart (qui ne sera pas montré)
Consultez l'aide générale sur Argus pour plus d'informations.
Code d’accès "spécial"
Un code d’accès dit "spécial" peut être associé à chaque activité. Ceci permet de protéger davantage les activités en question. Avant de pouvoir accéder aux AFO protégées de cette manière, les utilisateurs doivent entrer ce code spécial. Ce code d'accès est défini en AFO 611 – Modification code d’accès. Dans l’AFO 611 – Autorisations par AFO, vous pouvez déterminer pour chaque AFO si le code d'accès spécial est nécessaire.
Autorisations passives (de lecture seule) et actives (système : Sys!)
Au sein de l’AFO 243 "Gestion des budgets", de l’AFO 423 "Gestion des documents", de l’AFO 461 "Gestion des administrateurs, le système distingue les services de lecture des services de système (Sys!). Un ID utilisateur lié uniquement à un service de lecture ne permet en général que de visualiser et d’imprimer des données. En revanche, un ID utilisateur lié à
des services de système (Sys!) permet également de supprimer, de mettre à jour, d’ajouter, de saisir etc. des données.
Masquer les AFO
Vous pouvez masquer l’accès aux AFO pour chaque porte (logique) ; ainsi, vous serez en mesure d’indiquer quelles AFO peuvent être accessibles ou non sur une porte (poste de travail). Vous pouvez définir ceci dans l’AFO 612 "Gestion des ports". Cela vous permet d’associer de manière standard un ID utilisateur déterminé à certaines portes (logiques). Lors de l’ouverture d’une session, le système ne vous demandera plus d’entrer votre ID utilisateur, mais sélectionnera automatiquement l’ID utilisateur associé à la porte en question.

Cette option du menu vous permet d’associer certaines options à un usager. Vous pouvez interdire l’accès d’usagers à des options au sein du module de Périodiques. Cette option se rapporte aux AFOs 311, 321 et 368.
Si vous sélectionnez cette option du menu, un menu apparaît, affichant les options pouvant être associées à un usager:
Options du menu affichées à l’écran
Dans le menu, sélectionnez l’option de votre choix. Vous pouvez à présent ajouter des usagers à l’aide d’un écran de saisie ou, dans un écran-sommaire, ajouter et supprimer les usagers n’ayant pas accès à l’option en question.

611.122 Gestion des mots de pasGestion des mots de passese
Cette option de menu vous permet de définir différents paramètres liés aux mots de passe pour les IDs utilisateurs du personnel. Lorsque vous aurez sélectionné cette option du menu, un écran de saisie s’affichera:
Zones sur l'écran
Nbre de jours valable: Entrez le nombre de jours pendant lesquels un mot de passe demeure valable. Une fois ce délai expiré, l’utilisateur doit obligatoirement modifier son mot de passe lors de l’ouverture d’une session. Quelques jours avant la date d’échéance, le système avertira l’utilisateur à l’ouverture d’une session.
Nombre maximal de tentatives de connexions infructueuses autorisés : entrez le nombre de fois qu’un utilisateur peut saisir un mot de passe erroné. Quand ce nombre est atteint, le compte est verrouillé. Un aperçu de ces comptes verrouillés se trouve en AFO 611 – Sommaire des utilisateurs verrouillés, voir la section suivante pour plus d’informations.
Nombre de cycles pour ne pas permettre la réutilisation d’un ancien mot de passe : entrez le nombre de fois qu’un mot de passe doit avoir été changé avant qu’un mot de passe ancien puisse être utilisé à nouveau. Ceci a pour but d’empêcher la ré-utilisation immédiate d’un ancien mot de passe.
Longueur minimale et Maximale : entrez les limites de longueur du mot de passe.
Caractères spécifiques : indiquez quels caractères spécifiques sont obligatoires dans les mots de passe du personnel.

611.15
611.15 Rôles autorisationsRôles autorisations
Il est possible de copier les paramètres d’un ID utilisateur vers un autre ID. Cependant, il peut être nécessaire de copier d’un ID vers plusieurs autres IDs. Cette option de menu vous permet de le faire.
Cela repose sur 2 paramètres dans la définition d'un ID utilisateur dans l'AFO 611 – Gestion utilisateurs:
- Rôle d’autorisations
- Ceci est un Rôle d’autorisations
Si le 2ème paramètre est coché pour un utilisateur, alors cet utilisateur a les caractéristiques d’un rôle d’autorisations. Cela implique que toutes les autorisations et restrictions définies pour utilisateur forment un ensemble qui peut être copié.
Le 1er paramètre est lié à une liste déroulante avec tous les rôles d’autorisations définis. A partir de là, un rôle d’autorisations peut être associé à l’utilisateur sélectionné. Quand un nouveau rôle d’autorisations est associé à l’utilisateur, les autorisations et restrictions dans les AFOs définies au niveau du rôle vont l’emporter sur celles définies précédemment au
niveau de cet utilisateur (tous les paramètres copiés avec l’option Copier seront concernés par le rôle également).
Evidemment, un utilisateur ne peut pas être un rôle et en même temps avoir un rôle associé.
Lorsque vous sélectionnez cette option de menu, un écran sommaire s’affichera avec tous les rôles définis:
Options sur l'écran
Push des Autorisations: ici le “push” des autorisations et des restrictions définies au niveau du rôle est possible vers tous les utilisateurs associés au rôle sélectionné. Voir la section 611.15.2.
Utilisateurs: affichage des utilisateurs associés au rôle sélectionné. Ici, les utilisateurs peuvent être associés à un rôle ou dissociés d’un rôle. Voir la section 611.15.3.
611.15.1 Paramétrage
Cette section décrit plus en détail l'utilisation et l'effet des deux paramètres dans la définition de l'ID utilisateur.
611.15.1.1 Ceci est un Rôle d’autorisations
Ceci est un Rôle d’autorisations: si ce paramètre est coché pour un utilisateur, alors cet utilisateur a les caractéristiques d’un rôle d’autorisations. Cela implique que toutes les autorisations et restrictions définies pour utilisateur forment un ensemble qui peut être copié.
Le nom de l’utilisateur apparait maintenant en AFO 611 – Rôles autorisations comme “profil”. Un tel “utilisateur” n’est pas considéré comme un login standard, mais comme la base de la copie des autorisations et restrictions (en bloc).

611.15.1.2 Rôle d’autorisations
Rôle d’autorisations: est lié à une liste déroulante avec tous les rôles d’autorisations définis. A partir de là, un rôle d’autorisations peut être associé à l’utilisateur sélectionné. Quand un nouveau rôle d’autorisations est associé à l’utilisateur, les autorisations et restrictions dans les AFOs définies au niveau du rôle vont l’emporter sur celles définies précédemment au niveau de cet utilisateur (tous les paramètres copiés avec l’option Copier seront concernés par le rôle également).
Evidemment, un utilisateur ne peut pas être un rôle et en même temps avoir un rôle associé.

Push des Autorisations: ici le “push” des autorisations et des restrictions définies au niveau du rôle est possible vers tous les utilisateurs associés au rôle sélectionné.
